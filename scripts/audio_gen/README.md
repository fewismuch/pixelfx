# 特效音效生成流程（给 agent）

## 文件与入口

- 生成脚本从 Godot 项目的 `scripts/audio_gen` 复制而来；密钥读取环境变量 `VOLC_SPEECH_API_KEY` 或 `~/.config/volc_speech/api_key`。禁止将密钥写进项目或输出日志。
- `node tools/serve.mjs [端口]` 启动预览；打开 `/gallery/`，选择特效。
- 原音频：`audio/sfx/<分类>/<名称>/<批次 UUID>/candidate_01.wav` 到 `candidate_05.wav`。
- 同目录 `manifest.json` 记录候选、提示词、参考时长、实际时长、响度、真峰值、`timing` 和最终 `selected`。确认后仍沿用所选文件路径，不擅自重命名。
- 每批固定 5 个候选，一批最多 5 个并发请求；不同 agent 不要同时生成，避免超出总并发。再次生成追加新批次，不覆盖旧候选。

## 生成前先确定时序

1. 先执行 `node tools/show-fx-config.mjs <id>`，读取 `config/fx/<id>.json` 的已保存参数及实际时长；没有项目配置才使用源码默认参数。再读取 `src/fx/<id>.js`。查看 `meta.duration`、`fps`、`loop`、`draw/create` 内部阶段、命中与爆发时刻。不要仅凭技能名编提示词。 音效提示词必须覆盖实际存在的完整过程：出生/出现/显现、蓄力、释放、命中及消散；有出生或蓄力阶段就要写进去，不能只配命中或爆炸。只有用户明确要求单独某个阶段时才省略其他阶段，不凭空增加阶段。
2. 代码能清楚确定时序时无需导出帧图；时序不明确时，导出并查看带时间标注的帧图：`node tools/render.mjs <id> --all`，输出 `records/<id>/contact.png`。需要精确判断时用 `--fps 30` 或原始 `meta.fps`；默认 16 格抽样图不一定能捕捉短暂命中帧。可加 `--sheet` 导出序列帧和帧信息，必要时用 `--mp4` 看运动。
3. 优先由代码确定时间，必要时用帧图核对视觉，最终通过同步试听判断。第一帧有东西不等于第一帧就应播放命中声。例如：0–0.3 秒蓄力、0.3 秒爆发，若本次只生成爆发音效，则设置延迟 0.3 秒；音频从爆发开始，提示词时长约为特效剩余时长。技能若有明显蓄力，完整技能音效应包含蓄力、命中与余响；默认从蓄力开始，并在提示词说明命中的相对时刻。只有明确要求单独命中音效时，才省略蓄力。
4. `timing.offset` 的单位为秒：从预览循环开始到**音频文件开始播放**的延迟，按 1× 速度计；`timing.description` 简短记录用途、声音特点、阶段及时间依据。每个候选分别保存 timing。选中候选后保存时序只调整该候选；CLI 的 --offset/--description 配置下一批默认时序，并保留旧候选原时序。
5. 有 `export const act` 时还要读 `act.poses`、`act.hits` 和 `src/core/act.js`：预览可能从负时间的起手开始，命中 `t=0` 并不等于预览第一帧。用 `node tools/act.mjs <id>` / `--mp4` 检查完整表演。事件相对预览开始的延迟需计入起手及之前的停帧，不能直接拿 hits.t 当 offset。当前生成器的参考时长使用特效 `effectDuration`，不包含完整 act 起手、收招和停帧；遇到完整表演配音需求应先扩展生成器读取表演总时长，再生成，不要套用错误时长。
6. 多次命中优先以游戏/动画事件分别触发短音效；单条复合音频的内部节奏靠模型不保证精确。当前播放器只支持单条音频、一个整体延迟，不能宣称已支持多事件轨道。需要复合音效时，明确相对各个击打的时间并实际试听；不准则拆成独立事件后实现。

`lightning/sky-bolt` 已检查：`meta.duration=0.85`，第 0 帧就绘制闪电主体与落点闪光，因此 `offset=0`。首批 5 个候选实际均为 0.88 秒；这是模型生成结果，未裁切、拉伸或加静音。

循环特效在 gallery 里**每轮会硬重启整段音频**（不是把 wav 设为 `loop`），因此除提示词写稳态、无淡入淡出外，可对候选做首尾接缝：  
`python3 scripts/audio_gen/loop_seam.py <批次目录> <输出目录> --duration <特效秒数>`

## 生成 5 个候选

由 agent 分析特效、确认提示词与时序后，在项目根目录执行生成命令；网页负责试听、调整时序和确认保留：

```sh
node tools/generate-sfx.mjs lightning/sky-bolt --offset 0 --description '天降落雷，第一帧即劈中地面；短促雷电劈击后电火花自然消散。依据特效第 0 帧闪电与落点闪光。'
```

agent 应使用 `--prompt '完整提示词'` 提交自己编写的音效提示词，原文会保存在 manifest 中；省略时才使用脚本的自动拼接提示词。

已有经检查的时序配置时可直接 `node tools/generate-sfx.mjs <id>`。未保存时序说明会拒绝生成。生成器读取当前 `effectDuration`（默认读取项目配置，显式 options 按字段覆盖），扣除发声延迟后写入提示词。不把轮间停顿算进音频。若 tempo 等参数改变，阶段时间也必须按同一配置分析，不能直接照搬源码默认时刻。

提示词简短：用途、技能、声音特点、持续时间、自然结尾。等待由播放器调度，别让模型生成开头等待静音；别写过细的音色制作指令。普通延迟命中和包含蓄力的复合音效要明确区分。

## 检查与试听

需要 Python 3、ffmpeg、ffprobe。生成后自动测量实际时长、最大瞬时响度 LUFS 和真峰值 dBTP，悬停候选可看数据。试听每个候选，注意开头静音、命中同步、自然结尾、削波及音量差；模型的“立即发声”不是精确保证。必要时用 ffmpeg `silencedetect` 辅助检查，但不要把阈值检测当成听感或擅自裁切原文件。

点击候选：特效与音频从头同步循环，音频按已保存 offset 延后启动。保留原单次特效轮间约 0.45 秒停顿；长音频会在下一轮开始被停止。0.25×、0.5× 预览会同步缩放音频速度及延迟，音高也会变化。暂停、关闭、切到后台会停止/取消排队音效；恢复从头播放。切换特效不沿用上一特效的候选。

`normalize_sfx.py` 是原 Godot 项目工具，这里分析候选应加 `--all`；默认引用扫描仍针对 Godot。当前只测量，不自动调整响度、覆盖或裁切原音频；如要处理先保留原始文件并说明改动。

## 最终保留与后续打开

试听选择不代表授权删除。用户明确选定编号后 agent 可调用 `keepSfx(id, key)`，或用户点击“确认保留所选，删除其他候选”。该操作保存 `selected`，只删除此特效候选清单中的其他文件。不得猜选、提前删除、清理其他特效，或重新生成来代替用户选择。

之后点击打开此特效，会自动载入 `selected` 并同步循环播放，无需再次点击候选。首次打开需由浏览器点击/键盘操作解锁声音；静音开关会保留本次页面的静音状态。只在详细预览播放音频，分类列表中多个特效不会同时出声。

静态文件服务器不支持生成、保存时序与确认清理，必须使用更新后的 `tools/serve.mjs`。修改服务端代码后重启该服务。
